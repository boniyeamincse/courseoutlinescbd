01 / LEARNING GOAL

একটি alert, শুরু থেকে শেষ পর্যন্ত

কোর্স শেষে যা করতে পারবে

  • SIEM dashboard-এ alert queue review ও triage
  • Relevant logs থেকে evidence সংগ্রহ ও correlation
  • Severity, priority ও verdict-এর যুক্তি ব্যাখ্যা
  • Analyst comment ও case record তৈরি
  • Evidence-সহ escalation, handover অথবা closure

কাদের জন্য

নতুন SOC learner, IT support বা network professional এবং SOC L1 role-এ আগ্রহী শিক্ষার্থী।

শুরুর প্রস্তুতি

Basic networking, Windows/Linux পরিচিতি এবং browser ব্যবহারের দক্ষতা সহায়ক। Hands-on-এর জন্য training SIEM access অথবা sample alert/log dataset প্রয়োজন।

মূল ফোকাস: Alert Monitoring & Handling। Detection Rule Engineering বা custom rule writing এই ব্যাচের মূল পাঠ্যসূচি নয়।

Monitor Alert

02 / INVESTIGATE

Assignee, SOC Team, status এবং next action।

↗ EscalateL2 / IR / IT-তে timeline, evidence ও requested action-সহ পাঠানো।
✓ CloseClosure criteria পূরণ হলে findings, actions ও rationale-সহ বন্ধ করা।

প্রয়োজনে initial review-এর সময়ই owner নির্ধারণ করতে হবে। Critical finding পেলে পূর্ণ documentation-এর অপেক্ষা না করে SOP অনুযায়ী দ্রুত escalate করতে হবে; investigation চলাকালে record update হবে।

04 / CASE RECORD

প্রতিটি alert-এ কী পূরণ করবে

Fieldশিক্ষার্থীর কাজ
Alert MonitoringAlert শনাক্ত, review ও acknowledgement
ValidationLogs ও supporting evidence দিয়ে যাচাই
Severity & PriorityTechnical severity এবং business context অনুযায়ী অগ্রাধিকার
VerdictEvidence অনুযায়ী investigation outcome নির্ধারণ
Analyst CommentFindings, evidence, impact এবং action লেখা
Assignee & SOC Teamদায়িত্বপ্রাপ্ত analyst ও উপযুক্ত team নির্ধারণ
Statusকাজের বর্তমান অবস্থা ও next action update
Escalationপ্রয়োজনে উপযুক্ত tier-এ evidence-সহ পাঠানো
ClosureFindings, actions ও closure rationale সম্পূর্ণ করা
Training convention: Verdict, status ও team names এই কোর্সে ব্যবহৃত case-management model। এগুলোকে Wazuh-এর built-in ticketing fields ধরে নেওয়া হবে না; lab-এ প্রয়োজনমতো external case tracker বা worksheet ব্যবহার করা যাবে। Severity labels-ও course mapping; সরাসরি Wazuh numeric rule level-এর সমান নয়।

Duplicate এবং Test Activity disposition/tag হিসেবে আলাদা রাখা যাবে। “Suspicious / Undetermined” মানে investigation এখনো অসম্পূর্ণ; এটি evidence ছাড়া final malicious verdict নয়।

05 / ANALYST STANDARD

Evidence থেকে professional comment

একটি ভালো comment-এর উপাদান

  • কী ঘটেছে এবং কখন—timezone-সহ
  • কোন host, user এবং source IP জড়িত
  • কোন log/rule/event দিয়ে যাচাই করা হয়েছে
  • কী পাওয়া গেছে এবং কী এখনো অজানা
  • Verdict, rationale, action ও next owner

Evidence reference বা event ID সংযুক্ত করো; password, token বা অপ্রয়োজনীয় personal data case note-এ দিও না।

TRAINING EXAMPLE / SIMULATED CASE

Observed: LAB-WIN01-এ test-user account-এর জন্য 21:10–21:15 BDT সময়ে source 192.0.2.10 থেকে repeated failed logins এবং পরে একটি successful login দেখা গেছে।

Evidence: Authentication events; references AUTH-001–AUTH-012। User confirmation পাওয়া যায়নি।

Assessment: Suspicious / Undetermined। Successful login একাই compromise প্রমাণ করে না।

Next action: L2 validation requested; timeline attached, owner assigned, case status Escalated to L2।

06 / FINAL PRACTICAL

Class 12 — Full Alert Handling Assessment

চূড়ান্ত জমা

একটি simulated case-এর সম্পূর্ণ investigation record: timeline, evidence references, severity/priority, verdict, analyst comment, assignee/team, status ও next action।

  • প্রয়োজনে escalation summary ও handover
  • Closure হলে evidence-based rationale
  • Evidence অপর্যাপ্ত হলে uncertainty ও follow-up

Containment হবে অনুমোদিত SOP ও delegated authority অনুযায়ী। L1 analyst অনুমতি ছাড়া production host isolate বা account disable করবে না।
